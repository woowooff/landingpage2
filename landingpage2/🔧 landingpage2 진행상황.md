## 3. 현재 상태 (2026-08-04 실제 확인함)
- 로컬 서버는 정상 실행 가능 상태입니다. (지금 3000 포트에 하나 떠 있음)
- 신청 폼 제출은 서버로 전달되고, 성공 응답을 받을 수 있습니다.
- **메일 발송·시트 저장은 둘 다 아직 동작하지 않습니다.** `.env`의 인증값 4칸이 **전부 예시 문구 그대로**입니다.
  - `GMAIL_APP_PASSWORD` = `PUT_YOUR_..._HERE` ← 이전 노트에 "등록되어 있다"고 쓰여 있었으나 **사실이 아니었음**
  - `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `GOOGLE_PRIVATE_KEY` / `GOOGLE_SHEET_ID` 도 예시값
  - 채워진 것은 `GMAIL_USER` / `RECIPIENT_EMAIL`(둘 다 woogs4444@gmail.com)뿐
- ⚠️ **참고: `.env`에 `PORT=3000`이 있고 server.js가 `dotenv.config({override:true})`를 써서, 터미널에서 `PORT=3001`로 지정해도 무시되고 3000으로 뜹니다.** 포트를 바꾸려면 `.env`를 고쳐야 함.
- **미리보기(8000, 파이썬)와 신청서버(3000, node)의 연동은 이미 되어 있음** — `app.js:3`에서 8000번으로 열면 자동으로 `http://127.0.0.1:3000`으로 신청을 보냄. 실제 POST 테스트로 확인 완료.

### 🐞 발견하고 고친 버그 (2026-08-04)
- 증상: 신청을 넣으면 **성공이 아니라 실패(500)** 가 떴음. 진짜 신청자도 빨간 실패 화면을 봤을 상태였음.
- 원인 2가지
  1. 예시값 판별 함수(`hasConfiguredValue`)가 `PUT_YOUR_..._HERE` 같은 **밑줄형 예시 문구를 못 걸러냄**
     → 서버가 "비밀번호 채워졌다"고 착각하고 가짜 값으로 지메일 로그인 시도 → 구글이 `535 BadCredentials` 거부
     (패턴 목록에 `'YOUR_'`가 있었지만 비교 직전에 소문자로 바꿔서 영영 매칭되지 않는 죽은 패턴이었음)
  2. 메일 발송에 try/catch가 없어서, **메일 하나 실패하면 신청 접수 전체가 실패** 처리됨
- 조치: 예시값 패턴을 소문자·밑줄형까지 보강 + 메일 발송을 각각 try/catch로 감쌈
- 결과: 지금은 메일 설정이 없어도 **신청은 정상 접수되고 로컬에 저장**됨 (`.data/applications.json`, 테스트 포함 4건)
