# 제주다회 랜딩페이지 진행상황

## 1. 프로젝트 개요
- 프로젝트명: 제주다회 랜딩페이지
- 목적: 제주다회 소개, 신청 폼, 참가 신청 자동 처리 흐름 구성
- 현재 위치: D:\CLAUDE\jeju_vibe\landingpage2

## 2. 완료된 작업
- 정적 랜딩페이지 구조 구성 완료
- 프리미엄 스타일 디자인 적용 완료
- 신청 폼 UI 구성 완료
- 클라이언트에서 신청 데이터 전송 기능 연결 완료
- Node.js + Express 서버 구성 완료
- 신청 접수 API 구현 완료
- 메일 전송/Google Sheets 저장/로컬 백업 로직 연결 완료
- 로컬 테스트로 신청 접수 흐름 확인 완료

## 3. 현재 상태
- 로컬 서버는 정상 실행 가능 상태입니다.
- 신청 폼 제출은 서버로 전달되고, 성공 응답을 받을 수 있습니다.
- 다만 실제 메일 발송과 Google Sheets 저장은 .env에 실서비스 인증값이 들어와야 동작합니다.
- 현재 .env에는 Gmail 계정은 들어가 있지만, Google 서비스 계정 정보와 시트 ID는 플레이스홀더 상태이므로 자동화는 아직 비활성화된 상태입니다.

## 4. 주요 파일
- index.html: 랜딩페이지 구조
- styles.css: 디자인 스타일
- app.js: 폼 제출 처리
- server.js: 신청 API 및 자동화 로직
- .env: Gmail / Google 인증값 저장소
- SETUP_GUIDE.md: Gmail, Google Sheets 설정 가이드

## 5. 현재 확인된 이슈
- Gmail 앱 비밀번호는 .env에 등록되어 있지만, 실제 메일 전송 테스트가 완료되었는지는 추가 확인이 필요합니다.
- Google Sheets 연동은 서비스 계정 이메일, private key, sheet ID가 실제 값으로 들어와야 합니다.
- 서버 재시작 후 .env 값이 반영되는지 확인이 필요합니다.

## 6. 다음에 할 일
1. .env에 실제 Gmail 앱 비밀번호 입력
2. Google 서비스 계정 이메일, private key, Sheet ID 실제 값 입력
3. 서버 재시작 후 자동화 설정 상태 확인
4. 실제 신청 테스트로 메일 발송과 시트 저장 확인
5. 필요하면 배포용 환경으로 정리

## 7. 실행 방법
- 서버 실행:
  - node server.js
- 정적 미리보기:
  - python -m http.server 8000

## 8. 참고사항
- 신청 데이터는 로컬 백업 파일(.data/applications.json)에 저장됩니다.
- 메일/시트 자동화는 .env 값이 정상일 때만 동작합니다.
- 문제가 생기면 먼저 .env 값과 server.js의 설정 상태를 확인하세요.
